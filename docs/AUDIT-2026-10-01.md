# Audit Bearust — 1 Oktober 2026

Audit ini mencakup kode runtime HTTP/1–3, sinkronisasi control plane, dashboard, realtime, pengaturan, audit log, dependensi frontend, dan pengujian lokal. Ini bukan sertifikasi keamanan atau pembuktian bahwa semua target PRD sudah tersedia.

## Perbaikan yang diterapkan

1. **Identitas host runtime:** ID database kini diperbarui secara atomik bersama konfigurasi routing. Host baru/berganti domain tetap mendapat atribusi analytics dan pembatasan rate per-host yang benar. Request yang diblokir lebih awal juga memiliki identitas host.
2. **HTTP/3:** respons redirect upstream diteruskan, bukan diikuti otomatis; proxy lingkungan dinonaktifkan; timeout request mengikuti pool. Tahap lanjutan menerapkan timeout koneksi per pool dengan cache client terbatas yang mengikuti konfigurasi snapshot aktif. Body upstream terputus menghasilkan 502 sebelum header dikirim, atau reset HTTP/3 setelah respons mulai dikirim; analytics dan passive health mencatat kegagalan, bukan sukses/body lengkap.
3. **Realtime:** event security/cluster kini diteruskan; reconnect meresinkronisasi data dan mereset ID event koneksi; callback koneksi lama diabaikan. Notifikasi lag server memicu resinkronisasi karena belum ada replay persisten.
4. **Cluster:** perubahan Raft dan kesehatan peer menghasilkan event nyata; monitor backend berhenti bersama shutdown. Polling dashboard dipertahankan untuk memperbarui latency/timestamp ketika status tetap sama.
5. **Pengaturan:** preferensi notifikasi benar-benar disimpan per pengguna di browser dan digunakan untuk toast operasional. Kegagalan storage dan penyimpanan bahasa tidak lagi ditampilkan sebagai keberhasilan server. Tautan akun/session menuju halaman yang sesuai.
6. **Audit log:** pencarian backend mencakup label aktor; respons filter lama tidak menimpa hasil terbaru; ekspor CSV halaman aktif menetralkan formula spreadsheet. Tidak menambahkan endpoint export/mutasi riwayat.
7. **Dependensi:** patch tooling Vitest dan dependensi transitif diterapkan; `npm audit` sekarang melaporkan nol kerentanan. Ini hygiene build/test frontend, bukan klaim bahwa advisory tersebut mengeksploitasi runtime proxy. [Advisory Vitest](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9).

Regresi ditambahkan untuk reconnect/event realtime, penyimpanan preferensi, pesan bahasa offline, pencarian aktor, race filter, CSV formula, event cluster, redirect/timeout HTTP/3, serta host baru/rename dan rate policy. Tes regresi dijalankan gagal sebelum perbaikannya dan lulus setelahnya.

## Fitur yang belum lengkap / sengaja ditunda

- CAPTCHA provider eksternal dan trusted-crawler bypass berbasis ingress bertanda tangan; mekanisme challenge saat ini bukan integrasi penuh provider tersebut.
- ~~Lookup GeoIP database nyata~~ — selesai 10 Oktober 2026: `server.geoip_database` (MaxMind `.mmdb`) mengaktifkan aturan negara; CIDR `*` + kode negara untuk aturan seluruh negara. Lihat `docs/manual.md#ip-and-country-policies`.
- Retraining otomatis dari feedback false-positive adaptive tuning.
- Rollup analytics jangka panjang hourly/daily, agregasi lintas node, dan replay event realtime persisten.
  Agregasi query-time menit/jam/hari telah ditambahkan pada tahap lanjutan; itu tidak memperpanjang retensi atau menggantikan penyimpanan rollup jangka panjang.
- SSO/federated identity.
- Kompatibilitas penuh grammar Coraza/OWASP CRS: implementasi WAF saat ini terbatas, bukan pengganti identik seluruh engine/ruleset.
- Native upstream HTTP/3 adalah non-goal yang terdokumentasi, bukan fitur yang diam-diam selesai.
- Hot-reload TLS melalui transfer socket Pingora bergantung pada Linux. Request TLS diuji di macOS, tetapi reload listener lintas platform belum tersedia; deployment Linux tetap memerlukan verifikasi reload di platform tersebut.

Fitur-fitur ini membutuhkan rancangan/integrasi lebih luas; audit ini tidak mengarang implementasi atau mengaktifkan layanan eksternal tanpa konfigurasi. Prioritas lanjutan: parity timeout/protokol HTTP/3, cakupan keamanan ingress, lalu analytics dan integrasi identitas/provider sesuai kebutuhan deployment.

## Batas verifikasi

- Pengujian browser menggunakan mode demo; bukan pembuktian seluruh workflow terhadap server produksi.
- Integrasi Rust HTTP/3 dan cluster menggunakan socket/server lokal nyata.
- Docker daemon tidak tersedia: validasi konfigurasi Compose dan syntax script dilakukan, tetapi build/smoke container belum dapat dijalankan.
- Database eksternal PostgreSQL/MySQL, ACME publik, dan provider LLM memerlukan lingkungan/kredensial tersendiri; tidak diverifikasi live.
- File frontend legacy dan modul control-plane masih besar. Refactor menyeluruh tidak dicampurkan dengan perbaikan regresi ini.

Hasil frontend: 191 tes dalam 37 file lulus, build TypeScript/Vite lulus, validasi locale lulus, dan 10 tes Playwright demo lulus. `npm audit` (termasuk dev dependencies) melaporkan nol kerentanan. `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, dan pemeriksaan whitespace diff lulus.

Suite Rust menemukan fixture TLS salah `Content-Length` (11 untuk body 10 byte), database proses yang tidak terisolasi, serta fixture cluster in-memory yang kehilangan schema ketika koneksi dibatalkan saat shutdown. Fixture diperbaiki/dipindahkan ke database file sementara. Assertion transfer socket Linux dibatasi ke Linux; request TLS tetap diuji pada Unix lainnya. Suite lengkap dijalankan ulang setelah koreksi.

Verifikasi akhir `cargo test --workspace --locked --no-fail-fast`: **705 passed, 0 failed, 1 ignored**. Tes database eksternal yang tidak dikonfigurasi tidak membuktikan kompatibilitas live PostgreSQL/MySQL. Clippy seluruh target dijalankan ulang setelah perubahan fixture dan tetap lulus tanpa warning. Review kode independen tidak menemukan masalah penting pada perubahan yang ditinjau.

## Tahap lanjutan HTTP/3

Timeout koneksi per pool dan penanganan body upstream tidak lengkap sudah diterapkan. Cache client dibatasi 32 konfigurasi timeout; request membaca pool dari snapshot aktif, sehingga reload tidak mempertahankan nilai timeout lama. Timeout request tetap diterapkan terpisah. Respons buffered yang terputus tidak diteruskan ke transform plugin; streaming/oversized yang sudah dimulai di-reset dengan `H3_INTERNAL_ERROR`. Completion analytics/passive health mencatat 502, dan ukuran body upstream yang belum lengkap tidak diklaim sebagai bandwidth lengkap.

Tes baru menggunakan koneksi TLS lokal yang sengaja tidak menyelesaikan handshake untuk membuktikan perubahan deadline, dan upstream HTTP lokal dengan body lebih pendek daripada Content-Length untuk ketiga jalur respons. Assertion memeriksa kode reset dan analytics. Kegagalan awal berhasil direproduksi sebelum perbaikan.

Verifikasi tahap ini: **707 passed, 0 failed, 1 ignored**, termasuk seluruh 27 tes listener HTTP/3; Clippy seluruh target tanpa warning, format, dan whitespace diff lulus. Review independen tidak menemukan cacat implementasi penting; saran penguatan tes sudah diterapkan. Batas Docker, database/provider eksternal, serta reload TLS non-Linux tetap berlaku.
